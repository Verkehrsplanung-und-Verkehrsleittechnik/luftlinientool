AirlineTool2022

Create airline connections for given districts based on the RIN.

Application

Application via Dialog

Two options:

  • Visum version is not yet open:
    Start GUI externally (llt_GUI.py)
  • Visum version is already open:
    • Integrate execution of GUI (llt_GUI.py) into the script menu
    • Start script via script menu

    Note: If the GUI is started & closed several times, an error message may appear. This can be ignored, functionality is still ensured.

Call via Code

The AirlineTool can also be used without GUI. For this, a code execution must create an instance of the class AirlineCalculator.
Afterwards, the methods of the instance (Import, Calculation, Export) can be accessed.
An example can be found in Bsp_Aufruf_ohne_GUI.py.

Steps to execute

  1. Set parameters (which VFS, attribute values, etc.)
  2. Initialize AirlineCalculator object
    • Code: Call constructor with parameter transfer
    • GUI: Execute "Read Data" in the toolbar
  3. Calculate/generate airline connections
    • Code: Call calculate_main method
    • GUI: Execute "Airline network calculation" in the toolbar
  4. Export results to Visum in the desired form
    • Code: Call export_matrix/export_net methods
    • GUI: Use the corresponding buttons (Mtx/Net) in the column "create in Visum as".
      Alternatively, the button "Import into Visum all VFS routes + Mtx" transfers the combined results of all VFS.

Notes:

  • In the GUI, current calculations are reset if the selection of one of the district attributes is changed. A new instance of the LLT calculator is created.
  • If district values are changed in Visum, they are not automatically updated in the LLT calculator. Therefore, the procedure must be restarted from step 2.
  • The initial parameter values can be recalled in the GUI using the "Default values" tool.
  • "Initialize results" allows deletion of already existing results.
  • Step 3 uses the parameters currently entered in the GUI. Before calculation with new parameters, it is recommended to delete the existing results ("Initialize results").

Requirements

Network with categorized districts:

  • Attribute for centrality (districts): the smaller the number, the greater the centrality of the district

    Example: Indicating centrality via type number

    • 0 ... Metropolitan region
    • 1 ... Major center
    • 2 ... Medium center
    • 3 ... Basic center
    • 4 ... Place without central function
    • 5 ... Sub-district
  • (optional) active district filter
  • (optional) Attribute indicating which district is used as source {0=No, 1=Yes}
  • (optional) Attribute indicating which district is used as target {0=No, 1=Yes}
