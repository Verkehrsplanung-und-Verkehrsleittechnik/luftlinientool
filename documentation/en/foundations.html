General Procedure and Methodology

Calculation of Direct-Line Network for a Connectivity Function Level CFL

  1. Initialization and filtering of relevant traffic cells
  2. Calculation of triangle connections between traffic cells via Delaunay triangulation.
  3. Consideration of the n-nearest neighbors.
  4. Ensuring connection to supply centers.
  5. Filtering of traffic cells and connections.
  6. Creation of a symmetric adjacency matrix that correctly represents all connections.

This procedure is implemented in the function calculate_cfl (self, cfl) of the class directdistanceCalculator.

Initialization and Filtering of traffic cells

  • First, traffic cells with a centrality level ≥ CFL are filtered to include only those relevant for the current connectivity function level CFL. Traffic cells that are inactive or do not meet connection requirements are excluded.
  • A check is carried out to ensure that no traffic cells have identical coordinates.

Delaunay Triangulation

  • If there are enough active traffic cells, a Delaunay triangulation is performed to connect traffic cells into triangles. These triangles represent neighborhood relationships between traffic cells.
  • Delaunay triangulation connects two-dimensional points in such a way that no other points are contained within the perimeter of the resulting triangles. Note: The edge lengths are not minimised, but the Delaunay triangulation corresponds to a maximisation of the interior angle over all triangles.
  • The resulting neighborhood connections are stored in a (symmetric) adjacency matrix.
  • Connections of higher functionality level could be included as well, due to the consideration of traffic cells with centrality > CFL.

Consideration of n-Nearest Neighbors

  • Compute the reachability matrix of the adjacency matrix A for n steps:
    \(E_n = \sum_{k=1}^{n} A^k\)
  • Binarize the matrix:
    \(E_n^\text{bin} = \text{bin}(E_n)\)
    \((E_n^\text{bin})_{ij} = \begin{cases} 1, & \text{if}~(E_n)_{ij} > 0~\text{and}~i \neq j \\ 0, & \text{otherwise} \end{cases}\)
  • Set the main diagonal to zero.
  • Update adjacency matrix = binarized reachability matrix.

Connections to Supply Centers

  • Check whether each traffic cell is connected to a sufficient number of supply centers.
  • If not, determine the nearest supply centers and add connections.

Active and Inactive Connections

  • Only active traffic cells are considered as origin and destination of connections.
  • The "isOrigin" filter defines which traffic cell is used as an origin; "isDestination" defines the destination traffic cells. For symmetry reasons, the condition od = do applies. Nevertheless, "isDestination" traffic cells are not part of the triangles but are reached by the "isOrigin" traffic cells.
  • Implementation: A filter mask is applied to the adjacency matrices. This mask is the result of the dyadic product of "isOrigin" and "isDestination" followed by symmetrization.

Export of the Direct-Line Network for a CFL

The resulting direct-line connections can be exported as matrices or standalone infrastructure (nodes, link types, links, connectors) to PTV Visum.

Exporting the links of the resulting direct-line connections for the specified connectivity function levels as a standalone infrastructure (nodes, link types, links, connectors) allows visualization of the results or use of the resulting triangulation network.

When converting the adjacency matrices to infrastructure, two challenges must be addressed:

  • Compatibility with the existing infrastructure of the Visum model.
  • Avoidance of overlaps when combining multiple connectivity function levels and the correct assignment of CFL to links considered by multiple levels.

Therefore, the export of the direct-line network infrastructure is performed in two steps:

  1. If needed, update the required infrastructure objects (nodes, link types, links, connectors), taking into account all calculated adjacency matrices, and store them as attributes of the direct-line network calculator instance.
    This is implemented in the function extract_net of the class DirectLineNetworkCalculator.
    The numbering of objects relevant for Visum considers existing objects in the active Visum instance.
  2. The function export_net creates a .net file containing the infrastructure of the chosen connectivity function levels and imports it into the current Visum instance.
