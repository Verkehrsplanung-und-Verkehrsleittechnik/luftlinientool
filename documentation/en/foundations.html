General Procedure and Methodology

Determination of Connections for a Connection Function Level CFL

  1. Initialization and filtering of zones
  2. Determination of triangle connections between zones via Delaunay triangulation.
  3. Consideration of the n-nearest neighbors.
  4. Ensuring connection to supply centers.
  5. Filtering of zones and connections.
  6. Creation of a symmetric adjacency matrix that correctly represents all connections.

Implemented in the function calculate_cfl (self, cfl) of the class directdistanceCalculator.

Initialization and Filtering of zones

  • First, zones with level ≥ CFL are filtered to include only those relevant for the current connection function level CFL. zones that are inactive or do not meet connection requirements are excluded.
  • A check is performed to ensure that no two zones share identical coordinates, as this could cause issues during Delaunay triangulation.

Delaunay Triangulation

  • If there are enough active zones, a Delaunay triangulation is performed to connect zones into triangles. These triangles represent neighborhood relationships between zones.
  • The resulting neighborhood connections are stored in a (symmetric) adjacency matrix.
  • It can also identify connections to higher function levels (zones of connection level > CFL).

Consideration of n-Nearest Neighbors

  • Compute the reachability matrix of the adjacency matrix A for n steps:
    \(E_n = \sum_{k=1}^{n} A^k\)
  • Binarize the matrix:
    \(E_n^\text{bin} = \text{bin}(E_n)\)
    \((E_n^\text{bin})_{ij} = \begin{cases} 1, & \text{if}~(E_n)_{ij} > 0~\text{and}~i \neq j \\ 0, & \text{otherwise} \end{cases}\)
  • Set the main diagonal to zero.
  • Update the adjacency matrix to be the binarized reachability matrix.

Connections to Supply Centers

  • Check whether each zone is connected to a sufficient number of supply centers.
  • If not, determine the nearest supply centers and establish connections.

Active and Inactive Connections

  • Only active zones are considered as sources and targets of connections.
  • The "isSource" filter defines which zone is used as a source; "isTarget" defines the target zones. For symmetry reasons, the relations od = do hold. Nevertheless, "isTarget" zones are not part of the triangles but are reached by the "isSource" zones.
  • Implementation: A filter mask is applied to the adjacency matrices. This mask is the result of the dyadic product of "isSource" and "isTarget" followed by symmetrization.

Export of the Direct Distance Infrastructure for CFL

Exporting the computed Direct Distance links for the specified connection function levels as a standalone infrastructure (nodes, link types, links, connectors) allows visualization of the results or use of the resulting triangulation network.

When converting the adjacency matrices, two challenges must be addressed:

  • Compatibility with the existing infrastructure of a Visum model.
  • Avoidance of overlaps when combining multiple connection function levels and correct assignment of CFL to links considered by multiple levels.

Therefore, the export of the Direct Distance infrastructure is performed in two steps:

  1. If needed, update the required infrastructure objects (nodes, link types, links, connectors) taking into account all calculated adjacency matrices, and store them as attributes of the instance of the Direct Distance Tool calculator.
    This is implemented in the function extract_net of the class directdistanceCalculator.
    The numbering of objects relevant for Visum considers existing objects in the active Visum instance.
  2. The function export_net creates a .net file containing the infrastructure of the chosen connection function levels and opens it in the current Visum instance.
